# PR #142 - `rm -rf <HOME>/.fuse-harness/state` is `ask` instead of `deny` off macOS TMPDIR

## Root cause (code missing, not a wrong expectation)
`runGuards` (`src/policy/guards/index.ts`) returns the first non-null guard. `securityGuard` (position 3) returns the
generic `rm` ask (`security.ts` ASK_PATTERNS `\brm\s`) before `protectedPathGuard` (position 4) can deny.
The old tests passed on macOS only because `$TMPDIR` is `/var/folders/...`, which matches `SYSTEM_DIR_RE`
(`security.ts:15`, `/var\b`): an unrelated critical block that fired by accident.

## Repro (guard chain through `handleHook`, claude-code; before the fix)
| HOME form | `rm -rf/-r <state>` | `rm <key>` |
|---|---|---|
| /tmp, /private/tmp, /home/u, /Users/u, /root, /opt/x, symlinked HOME | ask | ask |
| /var/folders, /var/tmp | deny (accident: `/var`) | ask (without -f) |
After the fix: deny for every form (test `receipt-tamper-homes.test.ts`, 11 homes x 15 commands).

## Fix (hardening only)
- `src/policy/guards/protected-path.ts`: `receiptStoreGuard` = only the state-dir/key rule of `protectedPathGuard`.
- `src/policy/guards/index.ts`: when a guard returns `ask`, `denyOverAsk` returns `receiptStoreGuard`'s block if any; if it throws the ask stands.
- `docs/guards.md`: one paragraph.
- Hosts: claude-code, codex, cursor, kimi all `deny`, never a CONFIRM, for `rm -rf <state>` and `rm <key>` (and `find -exec rm`, `unlink`, `(rm ..)`).

## Differential (old = first-non-null loop over GUARDS, new = runGuards; 41 commands): 7 moved, all ask -> block
Moved: `rm -rf/-r` state, `rm` key, `find <state> -exec rm`, and the `~`, `$HOME`, `"$HOME"` forms of `rm -rf <state>`.
Unchanged (same verdict before/after): `.fuse-harness-other`, `.fuse-harness/../x`, `cache/x`, `states`, `.keyboard`, `.key.bak`,
`/tmp/x`, project `state`, `./state`, `find -delete`/`mv`/`cp` outside the state dir, `.git/x`, plugins cache, `unlink /tmp/x`,
installs, `sudo`, `eval`, reads of key/state, `cd <home> && rm -rf state` (documented limit: stays ask).
Challenger (78-command corpus): 17 moved, all ask -> block, each one a command `protectedPathGuard` alone already blocks. Residual by design:
the match ignores HOME, so `rm -rf /tmp/proj/.fuse-harness/state` is now deny (as `mv`/`cp`/`>` already were).
Not covered (still ask, a human confirms): `sh -c '...'`, `bash -c`, `xargs rm`, globs, `cd` then relative.

## Assertions changed (each tightening, with the line producing the new verdict)
- `receipt-tamper-guards.test.ts` "find <state> -exec rm" ask -> deny, and "rm of absolute key after escaped space" ask -> deny (a literal-`~` variant added, stays ask):
  new verdict from `index.ts` `denyOverAsk` -> `protected-path.ts` `receiptStoreGuard` (`newPathTargets(...).some(hitsNewPath)`); `hitsNewPath` exempts a word after an escaped space only when it starts with `~`/`$`.
- `receipt-tamper-data.test.ts` (PR #141, `src/tracking/track-verify.ts`): `replay_into_other_session` true -> false (line 47, `foreign-session`),
  `reorder_changes_verdict` false -> true (line 51, `duplicate-or-reorder`), `duplicate_lines_counted_once` true -> false (line 51, same reason: a duplicate breaks the chain).
- Helper `test/helpers/receipt-tamper-probe.ts` ported to main: `parseEvents` no longer exists (local MAC-only parser via `parseLine`/`lineMacOk`);
  the key-swap attacker now restarts the chain (rm log + head, `appendEvent` under the swapped key) so `after_key_swap_attacker_line_valid` stays `true` (assertion unchanged; challenger caught it).
